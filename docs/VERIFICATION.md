## 一、自动化测试

测试只使用虚构凭据和模拟厂商。Windows 上会调用插件真实的 DPAPI 实现，并清理自己创建的临时目录。

| 检查 | 结果 | 命令 |

| 语法检查（5 个模块） | 通过 | `npm run check` |
| Node.js 全部测试 | 43 个用例：41 通过、2 跳过、0 失败 | `npm test` |
| Magpie 自带的 Bun 1.4.4 | 43 个用例：41 通过、2 跳过、0 失败 | `bun test --timeout 30000 ./tests` |

2 个跳过项：隔离宿主集成测试默认不运行（需要 `MAGPIE_HOST_SCRIPT`）；“非 Windows 拒绝明文回退”只在非 Windows 上运行。

覆盖范围：5h / 7d 窗口按时长识别、只有 7 天窗口的套餐、不合规响应被拒、100% 额度门禁、仅监控账号隔离、多账号凭据隔离、失败与取消分支、三种协议的请求头替换、认证信号时序（拒绝后恢复、旧结果不覆盖新决策）、DPAPI 真实往返与损坏密文、vault 引用校验与旧位置兼容，以及“宿主只发现一个插件入口”。

### 隔离宿主集成测试

把本插件加载进 Magpie 自带的插件宿主，使用全新的临时配置目录、真实 DPAPI 和模拟厂商，验证：单一插件入口、两个账号、空 URL 的自动回调、账号文件里没有明文密钥、占位 `apiKey`、三种协议与 SSE 透传、100% 与故障门禁，以及两个账号相互独立。运行时只需指定宿主脚本，**不要**填写现有配置或账号文件：

```powershell
$env:MAGPIE_HOST_SCRIPT = '<Magpie 插件宿主脚本的绝对路径>'
bun test --timeout 60000 ./tests/host.integration.test.mjs
Remove-Item Env:MAGPIE_HOST_SCRIPT
```

宿主脚本在 Magpie 的缓存目录（`%USERPROFILE%\.cache\magpie\plugin-host\host-*.js`，选与当前 Magpie 版本对应的最新一个），Bun 使用 Magpie 自带的（`%USERPROFILE%\.cache\magpie\bun\<版本>\magpie-bun.exe`）。测试会创建并清理自己的临时目录，并拒绝模拟厂商之外的所有网络目标。

## 二、真实环境运行记录

维护者在自己的 Windows 机器上，以“本地文件夹”方式运行本版本（统计区间 2026-11-11 14:44 至 15:22，UTC+8）：

- 3 个账号（均含 Runtime Key）通过 Magpie 路由组使用；本版本启用后约 800 次推理请求全部返回 HTTP 200，3 个账号都有流量。
- 这些账号由 v1.0.1 创建，加密凭据仍在 v1.0.1 的旧位置，升级后继续可读，说明旧位置兼容在真实环境中生效。
- Magpie 的账号记录里没有明文的 Control Key / Runtime Key；每个账号的用量卡都显示 5 小时与 7 天窗口。
- 旧的“已退出登录”标记在本版本启用后不再保留（维护者确认）。
- **覆盖面有限**：真实流量只有 `deepseek-v4.1-flash` 经 `/v1/chat/completions`；`/v1/responses`、`/v1/messages` 以及其他模型还没有真实请求记录。
- **流式中断**：同一天较早时曾出现 2 次“HTTP 200 之后连接中断”（一次超时、一次 ECONNRESET）。据时间线判断，两次都发生在 1.0.3-rc.1 上线之前，当时 DPAPI 还是同步调用，运行环境也使用了本地 HTTP 代理。DPAPI 改为异步后，到统计结束时没有再出现，但样本有限，不能据此认定原因。
