# 路由配置与验收

插件只提供账号模型、额度窗口和请求前门禁；账号排序、重试以及跨供应商回退由 Magpie 负责。界面入口和可选策略以已安装的 Magpie 版本为准。

## 同供应商多账号

1. 在测试环境添加两个带 Runtime Key 的账号 A / B，各字段必须同属该账号。
2. 检查每个账号的 5h / 7d 窗口和重置时刻，与 OpenDesign 控制台一致。
3. 把两个账号加入所选模型的路由，选择界面提供的智能或用量优先策略，并允许故障转移。
4. 向测试路由发送一次小请求，在 trace 里查看实际使用的账号；暂停 A，确认 B 可以承接，随后恢复。
5. 仅监控账号应该只有额度卡片，没有模型候选。

## 跨供应商回退

在 Magpie 里新建测试路由组，明确加入 `opendesign-local/<实际模型 ID>` 和已配置的备用供应商模型。不要直接修改生产 Agent 的模型或原有路由。

依次暂停主要账号、备用账号，检查允许的目标和最终的失败行为，再恢复所有设置。“账号 B 单独能调用”不等于宿主的自动故障转移已经通过，必须查看真实的路由 trace。

## 共享套餐的展示

多个账号使用同一 Control Key 和 Workspace ID、各自配置不同 Runtime Key 时，可在 Magpie 的 **用量 → 概览** 保留一张用量卡。打开其余卡片的菜单，选择 **从概览中隐藏这个账号**。这些账号仍可参加路由。

用现有账号名称合成一条共用别名，设置在保留的账号上。例如，保留 `Plan-High`，隐藏同套餐的 `Plan-Speed`。

```powershell
magpie accounts alias opendesign-local "Plan-High" "Plan-High / Plan-Speed · 共用"
```

第一个名称用保留的账号 ID，最后一个参数是显示别名。之后可以用同一命令修改别名。

## 门禁与限制

5h / 7d 任一窗口耗尽或额度未知时，插件返回本地 `429`。其他阈值由 Magpie 自己决定，插件不会把真实读数篡改成阈值。

流式 HTTP 200 之后断流不等于安全的故障转移：已经输出的内容和工具调用可能有副作用，请保留请求 ID 和已脱敏的错误信息，不要自动重放整次调用。

账号额度上限等设置以已安装版本的界面和文档为准。完整的验收清单见 [验收状态](VERIFICATION.md)。
